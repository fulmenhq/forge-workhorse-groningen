- **Control plane split**: Dedicated operational server on a separate port, loopback-bound by default

- **Full JSONSchema flavor support**: Draft-04 through Draft 2020-12 with auto-detection and meta-validation
- **ADR documentation**: Four Architecture Decision Records documenting key design decisions

## Feature 1: Control Plane / Data Plane Split

Separates operational endpoints from the primary API surface. The control plane runs on a dedicated server bound to loopback by default, enforcing security isolation without configuration.

### Two-Server Architecture

```
┌─────────────────────────────────────────────────────────┐
│                    groningen serve                       │
├─────────────────────────┬───────────────────────────────┤
│      Data Plane         │       Control Plane           │
│   (0.0.0.0:8080)        │    (127.0.0.1:9091)          │
├─────────────────────────┼───────────────────────────────┤
│ /health/*               │ /control/                     │
│ /version                │ /control/signal               │
│ /metrics                │ /control/config/reload        │
│ /* (user routes)        │                               │
└─────────────────────────┴───────────────────────────────┘
```

### Control Plane Endpoints

| Endpoint                 | Method | Description                        |
| ------------------------ | ------ | ---------------------------------- |
| `/control/`              | GET    | Discovery / status                 |
| `/control/signal`        | POST   | Signal injection (SIGHUP, SIGTERM) |
| `/control/config/reload` | POST   | Trigger config reload              |

### Configuration

```yaml
controlPlane:
  enabled: true
  host: 127.0.0.1 # Loopback by default (safe)
  port: 9091
  basePath: /control
  bearerToken: "" # Required if host is not loopback
```

### Safe-by-Default Invariants

- Control plane port MUST differ from data plane port
- If host is NOT loopback (`127.0.0.1` / `localhost`), a bearer token MUST be configured
- Bearer token auth middleware applied to all control plane routes

## Feature 2: Starter Auth Framework

Optional authentication for the data plane with simple, replaceable auth modes. Designed as an on-ramp for CDRL users — not a final security posture. Disabled by default.

### Auth Modes

| Mode          | Description                     |
| ------------- | ------------------------------- |
| `disabled`    | No auth (default)               |
| `bearerToken` | `Authorization: Bearer <token>` |
| `basicAuth`   | `Authorization: Basic <base64>` |

CDRL users are expected to replace these with OAuth, JWT, API keys, or their preferred auth strategy.

### Route Policy

Prefix-based categorization with longest-prefix matching:

| Category      | Behavior                                                             |
| ------------- | -------------------------------------------------------------------- |
| `deny`        | Return 404 (hide route existence)                                    |
| `public`      | No auth required                                                     |
| `conditional` | Auth optional; handlers receive auth context if credentials provided |
| `protected`   | 401 if not authenticated                                             |

### Default Route Policy

```yaml
dataPlaneAuth:
  enabled: false
  mode: disabled # disabled | bearerToken | basicAuth
  bearerToken: ""
  basicAuth:
    username: ""
    password: ""
  routePolicy:
    - prefix: /health
      category: public
    - prefix: /version
      category: public
    - prefix: /metrics
      category: conditional
    - prefix: /
      category: protected # Catch-all
```

### Request Context

Auth middleware attaches `auth.Info` to request context:

```go
info := auth.Get(r.Context())
if info.Authenticated {
    // info.Principal contains "bearer" or username
    // info.Category contains the matched route category
}
```

### Security

- Constant-time comparison for bearer tokens and passwords (`crypto/subtle`)
- Config validation enforces: if auth enabled, mode must not be `disabled`; if `bearerToken` mode, token must be non-empty; if `basicAuth`, both username and password must be non-empty

### Files Added

- `internal/server/auth/middleware.go` — Auth middleware with route policy enforcement
- `internal/server/auth/policy.go` — Route category types and longest-prefix matching
- `internal/server/auth/middleware_test.go` — Bearer/basic auth and deny tests
- `internal/server/auth/policy_test.go` — Prefix matching tests

## Feature 3: Env Var Canonical/Alias Ergonomics

Supports both canonical (nested) and alias (short) environment variable names. Canonical names mirror the config YAML structure; aliases preserve the shorter forms for convenience and backward compatibility.

### Naming Convention

| Canonical (nested)                  | Alias (short)                     | Config Path             |
| ----------------------------------- | --------------------------------- | ----------------------- |
| `GRONINGEN_SERVER_HOST`             | `GRONINGEN_HOST`                  | `server.host`           |
| `GRONINGEN_SERVER_PORT`             | `GRONINGEN_PORT`                  | `server.port`           |
| `GRONINGEN_LOGGING_LEVEL`           | `GRONINGEN_LOG_LEVEL`             | `logging.level`         |
| `GRONINGEN_LOGGING_PROFILE`         | `GRONINGEN_LOG_PROFILE`           | `logging.profile`       |
| `GRONINGEN_CONTROL_PLANE_ENABLED`   | `GRONINGEN_CONTROLPLANE_ENABLED`  | `controlPlane.enabled`  |
| `GRONINGEN_CONTROL_PLANE_PORT`      | `GRONINGEN_CONTROLPLANE_PORT`     | `controlPlane.port`     |
| `GRONINGEN_DATA_PLANE_AUTH_ENABLED` | `GRONINGEN_DATAPLANEAUTH_ENABLED` | `dataPlaneAuth.enabled` |

### Conflict Detection

When both canonical and alias are set with different values:

1. A warning is logged with both values
2. The **alias takes precedence** (more specific intent)

```
WARN: Environment variable conflict detected
  GRONINGEN_PORT=9000 (alias)
  GRONINGEN_SERVER_PORT=8080 (canonical)
  Using alias value: 9000
```

### Sensitive Value Masking

Values for keys matching `TOKEN`, `SECRET`, `PASSWORD`, `KEY`, or `CREDENTIAL` are masked as `[set]` in all diagnostic output.

### Files Added/Modified

- `internal/config/envvars.go` — `EnvVarMapping` struct, `EnvVarMappings()`, `EnvVarSpecs()`, `MaskEnvValue()`
- `internal/config/loader.go` — Alias-aware config loading with conflict warnings

=====================
Canonical                              Alias                              Effective    Source

- Actionable recommendations for each issue found

Exposes multi-draft schema validation inherited from the gofulmen/crucible dependency upgrade. CDRL users can now use any major JSONSchema draft in their applications without configuration.

### Supported Drafts

| Draft         | `$schema` URI                                  | Status    |

| Draft-04      | `http://json-schema.org/draft-04/schema#`      | Supported |
| Draft-06      | `http://json-schema.org/draft-06/schema#`      | Supported |
| Draft-07      | `http://json-schema.org/draft-07/schema#`      | Supported |
| Draft 2019-09 | `https://json-schema.org/draft/2019-09/schema` | Supported |
| Draft 2020-12 | `https://json-schema.org/draft/2020-12/schema` | Supported |

Auto-detection from the `$schema` field — no configuration required.

## Migration Notes

### For Existing CDRL Consumers

**No breaking changes.** Drop-in compatible.

- Control plane is enabled by default on `127.0.0.1:9091` — no action required unless you want to customize
- Data plane auth is disabled by default — no behavior change
- Existing env vars (e.g., `GRONINGEN_PORT`) continue to work as aliases
- New canonical env var names are additive and optional

### For New CDRL Users

See the [CDRL Guide](../development/fulmen_cdrl_guide.md) for template refitting instructions. Key additions:

- Customize `controlPlane` settings in your defaults YAML
- Set `dataPlaneAuth.enabled: true` and configure mode/token when ready for auth
- Update `.fulmen/app.yaml` `env_prefix` and all env var mappings auto-adjust
